Utility methods and functionalities for Guile Scheme programming.

kracht is a recursive acronym which stands for /KRACHT Reliable And Consistent Helper Tools/, and it also means means power/strength in the Dutch language.

Kracht provides helpful and convenient custom functionalities as well as re-exports from the standard library that can help you develop more comfortably and faster in your Guile Scheme project.  You can see it as a batteries-included enhancement to the (already great) standard library, complementing it, and helping developers write cleaner code.

** Modules

Kracht is organised into small, focused modules.  ~(kracht prelude)~ is the
umbrella module that re-exports everything below, so a single
~(use-modules (kracht prelude))~ keeps working; but you can also import only
what you need:

- ~(kracht strings)~ — string predicates and helpers (~non-empty-string?~,
  ~empty-string?~, ~string-drop-first-last~, ~string-drop-first-last-n~,
  ~string-drop-first-last-line~, ~base64-encode~ / ~base64-decode~), plus
  re-exports of ~string->utf8~, ~utf8->string~ and ~string-replace-substring~.
- ~(kracht lists)~ — ~flatten-list~, association-list helpers (~assoc-lens~,
  ~assoc-ref-or~, ~assoc-ref-or-empty-str~, ~alist-set~, ~alist?~),
  ~evaluate-thunks~ and ~shuffle-fy~.
- ~(kracht sql)~ — ~symbol->sql-column~, ~sql-column->symbol~,
  ~symbols->sql-columns-list~, ~sql-row->scheme-alist~, ~escape-sql-string~,
  ~quote-sql-identifier~, ~pair->sql-assignment~ and ~value->sql-literal~.
- ~(kracht web)~ — ~html-escape~, ~html-unescape~,
  ~alist-from-url-encoded-body~, plus re-exports of ~uri-decode~ and
  ~uri-encode~.
- ~(kracht io)~ — ~read-file-string~, ~write-file-string~,
  ~build-asset-library~, ~syscall~, ~get-short-commit-sha~, ~getenv-or~ and
  the port re-exports.

** Re-exports from the standard library

So that a single ~(use-modules (kracht prelude))~ is often enough, Kracht
re-exports a large and growing set of commonly used procedures that Guile's
core does not already provide:

- *SRFI-1* list procedures: ~fold~, ~fold-right~, ~reduce~, ~reduce-right~,
  ~filter-map~, ~find~, ~find-tail~, ~any~, ~every~, ~count~, ~list-index~,
  ~list-tabulate~, ~take~, ~drop~, ~take-while~, ~drop-while~, ~span~,
  ~break~, ~partition~, ~delete-duplicates~, ~append-map~, ~zip~,
  ~unzip1~ through ~unzip5~, the ~lset-*~ family, the destructive
  (~!~-suffixed) variants, and more.
- *SRFI-2* ~and-let*~
- *SRFI-8* ~receive~
- *SRFI-11* ~let-values~, ~let*-values~
- *SRFI-26* ~cut~, ~cute~
- *SRFI-43* vector procedures: ~vector-fold~, ~vector-map~, ~vector-for-each~,
  ~vector-append~, ~vector-count~, ~vector-unfold~, ~vector=~ and friends.
- *SRFI-111* boxes: ~box~, ~box?~, ~unbox~, ~set-box!~
- *SRFI-19* date and time: ~current-date~, ~make-date~, ~make-time~,
  ~date->string~, ~string->date~, ~time-utc~, ~time-monotonic~,
  ~time-difference~, and more.
- =(ice-9 match)=: ~match~, ~match-lambda~, ~match-lambda*~, ~match-let~,
  ~match-let*~, ~match-letrec~.
- =(ice-9 pretty-print)=: ~pretty-print~, ~truncated-print~.
- =(ice-9 format)='s ~format~ comes from Guile's core and is available as
  usual.

Guile's core module already provides the whole of *SRFI-13* (the string
library), ~case-lambda~, string ports, records and parameters, so Kracht does
not re-export those: you already get them for free.

Hash tables are intentionally *not* re-exported. Guile's native
~make-hash-table~ and SRFI-69's ~make-hash-table~ are different, incompatible
types, and silently replacing one with the other could break existing code, so
Kracht leaves Guile's native hash tables untouched.

** Extra helpers

Beyond the re-exports, Kracht adds convenient helpers such as:

- ~read-file-string~ and ~write-file-string~ for whole-file reading/writing.
- ~assoc-ref-or~ and ~alist-set~ for working with association lists.
- ~escape-sql-string~, ~value->sql-literal~ and ~pair->sql-assignment~ for
  building SQL, with single quotes escaped; ~quote-sql-identifier~ for safely
  quoting column and table names.
- ~html-escape~ / ~html-unescape~, ~base64-encode~ / ~base64-decode~,
  ~flatten-list~, ~string-drop-first-last*~, ~shuffle-fy~, ~syscall~,
  ~getenv-or~, ~get-short-commit-sha~ and more.


* Runtime Dependencies

Kracht has minimal dependencies and needs only GNU Guile Scheme itself (3.0 or
newer).  In particular, base64 encoding and decoding are implemented in pure
Scheme, so no external ~base64~ binary is required and no shell is spawned for
them.


* Behavior notes

A few functions were tightened for robustness in recent versions:

- ~non-empty-string?~ now returns ~#t~ only for actual non-empty strings.  It
  used to return ~#t~ for any truthy value (for example ~#t~ itself).
- ~base64-encode~ / ~base64-decode~ are pure Scheme.  The encoder no longer
  appends a trailing newline and the decoder ignores whitespace in its input.
- ~alist-from-url-encoded-body~ splits each segment on the first ~=~ only, so a
  value may contain ~=~, and empty segments are skipped.
- ~html-escape~ now escapes the ampersand too, so it covers all five
  HTML-significant characters (~&~, ~<~, ~>~, ~"~ and ~'~).  Escaping is
  deliberately *not* idempotent: ~"&amp;"~ becomes ~"&amp;amp;"~, so escape
  raw text exactly once.  It no longer rewrites ~/~, ~*~, ~$~ or ~%~, which
  HTML never required and which corrupted plain text; ~html-unescape~ still
  decodes those entities, plus numeric character references such as ~&#39;~ and
  ~&#x27;~ and the uppercase legacy spellings ~&AMP;~/~&LT;~/~&GT;~/~&QUOT;~.
- ~escape-sql-string~ rejects strings containing a NUL character, which no SQL
  text type can store, and accepts ~#:escape-backslash?~ for MySQL/MariaDB,
  whose parser also treats a backslash as an escape character.
- ~quote-sql-identifier~ is new: it wraps a symbol or string in ANSI double
  quotes and doubles any embedded double quote, for column and table names
  that come from data.
- ~shuffle-fy~ accepts a ~#:state~ argument for deterministic shuffling and no
  longer reseeds Guile's global random state.
- ~pair->sql-assignment~ and ~value->sql-literal~ escape single quotes; prefer
  bound parameters rather than building SQL by string interpolation.
- ~string-drop-first-last-n~ clamps ~n~ instead of raising an error.
- ~get-short-commit-sha~ trims its output and accepts a ~#:default~ value for
  when no SHA can be determined.

* Installing and using

kracht is packaged via the Guix package manager officially, as ~guile-kracht~. It is recommended you use Guix to work on your Guile Scheme projects, and install kracht with it (in your manifest.scm for example).

Alternatively, you can install it by downloading the source code files and adding them directly to your ~GUILE_LOAD_PATH~ or even better, use a Guix shell ~manifest.scm~ and add the package with something like this:

#+begin_src scheme
(define-public guile-kracht
  (package
    (name "guile-kracht")
    (version "x.x.x")
    (source
     (origin
       (method git-fetch)
       (uri (git-reference
             (url "https://codeberg.org/jjba23/kracht.git")
             (commit (string-append "v" version))))
       (file-name (git-file-name name version))
       (sha256
        (base32 "<dependent on version>"))))
    (build-system guile-build-system)
    (native-inputs (list guile-3.0))
    (arguments
     (list
      #:source-directory "src"))
    (home-page "https://codeberg.org/jjba23/kracht")
    (synopsis
     "Utility methods and functionalities for Guile Scheme programming")
    (description
     "Kracht provides helpful and convenient functionalities that can help you
develop more comfortably in your Guile Scheme project.  You can see it as a
batteries-included addition to the (already great) standard library,
complementing it, and helping developers write cleaner code.")
    (license license:lgpl3+)))
#+end_src

* On Reproducibility: Why GNU Guix?

A build should never fail because "it worked on my machine." Reliable software development requires explicit, bit-for-bit reproducibility and a functional approach to package management and system deployment.

#+BEGIN_EXPORT html
<a href="https://guix.gnu.org/">
  <img src="https://jointhefreeworld.org/ggg/dist/gnu-guix.svg" alt="GNU Guix logo" style="max-width: 250px; width: 100%; height: auto;" />
</a>
#+END_EXPORT

- *Declarative Build Graphs:* Packages are pure functions of their inputs with no implicit system state.
- *Programmable with Guile:* Full system and package configurations written in [[https://www.gnu.org/software/guile/][Guile Scheme]] rather than rigid DSLs or static files.
- *Time Travel:* Rebuild the exact system state from any point in git history using ~guix time-machine~.
- *Atomic Operations:* Instantly upgrade or roll back environments without leaving orphaned dependencies or broken states.
- *Unified Tooling:* One tool manages development shells, isolated containers, package builds, and full system configurations.
